# tests/host/orient — 自适应屏幕方向的判定核

把 `main/hw/auto_orient_core.h` 拿到 Linux x86-64 上用普通 `g++` 跑一遍：喂合成的重力
向量，断言状态机的输出序列。没有 ESP-IDF、没有 CMake、没有设备、**也没有 stub** ——
那个头只 include `<stdint.h>`，是刻意的（见下）。

## 跑

```sh
tests/host/orient/run.sh      # 全部场景，逐项打印 ok/FAIL，失败 rc=1
```

什么都不写出去，除了 `build/`（gitignored）。

## 为什么判定核单独一个头

这个功能里唯一有分歧、值得反复调的是**判据**：门槛、余量、连续拍数、冷却、打字静默。
它跟 ESP-IDF、跟 board、跟主循环都没关系，所以切成一个零依赖的纯函数头，主机直接
include 就能把所有边界情形（死区、慢速翻转、甩动、噪声、冷却）过一遍，不用刷机。
硬件/界面那一半（采样、落地、模式策略）在 `main/hw/auto_orient.cpp`，那里没有可测的
分支，只有接线。

## 判据（常量都在 `auto_orient_core.h`）

- **有效重力** `|‖a‖ − 1000| ≤ 250mg`：静止时不管怎么斜 ‖a‖ 恒为 1g，所以这条筛的是
  **运动**，尤其"晃动机身=全刷"那次甩动。与 `hw/input.cpp` 的 `shake_poll()`（判据正是
  ‖a‖ 偏离 1g）天然互补，两边不吃同一口。
- **主轴门槛/余量** `|主轴| ≥ 350mg` 且 `|主轴| ≥ |副轴| + 450mg`：450mg 在 1g 上对应
  "偏离主轴约 26.6°"，±26.6° 内算这一档、26.6°~63.4° 是**死区**（判不出 = 保持现状）。
  死区宽是刻意的：手持晃动、支架斜靠都落在里面。
- **DWELL 4 拍**（≈0.5s 连续同向）+ **冷却 2500ms**（转一次是整屏 GC16 ≈1.8s）+
  **输入静默 800ms**（打字/划列表时屏幕不掉头）。

## 覆盖到的场景

| 场景 | 断言 |
|---|---|
| 姿态表（13 例） | 平放/竖着/横着/偏 25.5°(认)/偏 30°(死区)/45°/后仰 45°/甩动那一拍 |
| DWELL | 差一拍不转；凑满才转；转完拿着不反复转；两拍一换凑不满 |
| 慢速翻转 90° | 逐 5° 打印判定表；**整段只转一次**，且转点 = 首判竖屏之后再攒满 DWELL |
| 晃动 | ‖a‖ 冲出 1g 的几拍不判；静止后按新姿态转一次 |
| 冷却 | 2.4s 内姿态再变也不动；冷却一过立刻补（2520ms ≥ 2500ms） |
| 打字抑制 | 持续有输入时 30 拍都不转；停手后**下一拍**就补上（不重新攒 DWELL） |
| 搁桌上 | 200 拍平放噪声（横分量最大 150mg）一次都没转 |
| 停用/启用 | `aoc_reset()` 之后不拿上一次的 dwell 顶数 |

慢速翻转那一张表是最直观的：判定 `横屏 → 判不出(30°~60°) → 竖屏`，中间那 7 拍一拍都
没动。

## 真机上还要验什么

判定核在主机上是全绿的，但**有一位的真值只有设备知道**：`kPortraitIsXAxis` —— 设备帧
的哪根轴对应"竖屏"。静态推不出来（`read_pico_init.h` 只说了屏幕法线是 +Z，没说 X 对应
面板哪条边；芯片帧、触摸帧各自都换过坐标系），所以第一次上机要看日志：

```
auto-orient: x=900 y=40 z=300 → 竖屏
```

竖着拿机器，屏幕应该变竖。若竖着拿反而横屏，把 `auto_orient_core.h` 里那一个常量翻过来
重刷一次即可，别的一行都不用动。主机这边把它当参数：翻转常量后 `run.sh` 里的姿态表
期望值要跟着换（竖着拿那两行会变横屏），那是故意的 —— 它钉的就是这一位的语义。
